Key verified facts

The preview world runs Construct — never BeginPlay, never replication
UCk_EditorEcsWorld_Subsystem_UE (Editor worlds only, own EnTT registry, IsTickableInEditor) builds the full processor graph with ECk_ProcessorWorldTypeContext::Editor (CkEcsEditor_Subsystem.cpp:301-307). Processors declaring WorldTypeRequirement = RuntimeOnly become ghost nodes — edges kept, ForEachEntity never fires. FProcessor_EntityScript_BeginPlay, _Replicate, _PendingReplicationRetry are all RuntimeOnly (CkEntityScript_Processor.h:85,139,166). So previews get Construct + OnConstructed only. CONFIRMED by verifier.
ISKM's own module is editor-clean — the gap is the missing hardening pass, not a gate
Subsystem supports Editor/EditorPreview (CkIskmSubsystem.cpp:92-104), manager actor init is explicit (no BeginPlay reliance), no ISKM processor declares a world requirement, Utils Add has no world checks, and 96aeaf1dd even added a TIgnoreInEditor accommodation — editor preview is clearly intended. What's missing vs ISM: per-owner editor renderer + ck::editor_selection_owner integration (0 hits module-wide) and SetUpdateAnimationInEditor (0 hits) — so even a working preview would render a frozen, unselectable pose.
