6 — BusterBlock migration comes last

Why a direct update is unsafe
The framework default is GroundNav, while BusterBlock does not explicitly select Recast and currently has no authored GroundNav fields/manifests. Its eight Nav.Filter.* mappings reference legacy UNavigationQueryFilter classes rather than provider-neutral definitions. Its sidewalk vectorizer also directly queries ARecastNavMesh. A pointer-only update can produce NoData navigation and weakened filters.
  1. Explicitly pin BusterBlock to Recast and confirm its default Recast nav data exists.
  2. Migrate or bridge all eight query filters to neutral definitions.
  3. Update plugins in the existing checkout, then compile and run the existing Recast baseline.
  4. Introduce GroundNav on one isolated authored BusterBlock map; keep production worlds on Recast.
  5. Run editor, cook, real streaming/pathing and packaged matched A/B acceptance.
  6. Migrate one real map only after every prior gate is green.
  7. Exercise rollback: select Recast, confirm nav data, rerun affected routes, and archive evidence. Retain Recast.
