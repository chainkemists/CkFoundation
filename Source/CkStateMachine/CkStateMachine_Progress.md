## Design Decisions & Rationale

### 1. Everything Is an Entity
**Decision:** SM, States, Tasks, Transitions, and Conditions are all ECS entities with EntityScripts.
**Rationale:** Maximum flexibility. Users can optionally put logic directly on the State EntityScript OR keep it lean and delegate to Tasks. Entities can carry arbitrary fragments.

### 2. Dynamic Graph (Not Static)
**Decision:** The state graph is built by walking states at runtime, not defined statically in a data asset.
**Rationale:** Enables overriding states in derived classes, runtime graph modification, and programmatic state machine construction.

### 3. Flat States + Hierarchy via Tasks
**Decision:** No first-class hierarchical state support. A Task can spawn a sub-StateMachine.
**Rationale:** Keeps the core simple. Hierarchy emerges naturally from composition without adding architectural complexity.

### 4. Both Polled and Event-Driven Transitions
**Decision:** Transitions can either poll conditions every frame or be triggered by external events.
**Rationale:** Polled is simpler for common cases (health < threshold). Event-driven is more efficient for signal-based triggers (damage received, input pressed).

### 5. EntityScript Subclasses for Event-Driven Transitions
**Decision:** Users create a `UCk_SmTransition_EntityScript` subclass that binds to signals and calls `TriggerTransition()`.
**Rationale:** Full power from day one. The user controls exactly what signals trigger the transition and how.

### 6. PostConstructionFunc for State Handle Assignment
**Decision:** `DoEnterState` uses `UCk_Utils_EntityScript_UE::Add()` with a `PostConstructionFunc` lambda to set `_CurrentStateHandle` on the SM.
**Rationale:** Entity spawning is deferred in the ECS. The lambda fires after construction completes, ensuring the handle is valid before assignment.

### 7. Builder API on State EntityScript
**Decision:** `AddTask`, `AddTransition_Polled`, `AddTransition_EventDriven`, `AddCondition` are methods on `UCk_SmState_EntityScript`, called from `DefineState()`.
**Rationale:** Clean, declarative API. States define their structure in one place. UFUNCTION wrappers enable AngelScript usage.
