CkCrowdDebugger — UX Mockup

Static HTML+CSS approximation of the new debugger window. This is the canonical UX contract for the navigation rewrite — gate plans reference panels and fields shown in these pages instead of redescribing UX in prose. No JavaScript; all interactivity is illustrative only.

01 — Primary view (agent selected)

The full debugger with one agent selected. Every panel populated. Use this to see the maximum data depth and the visual hierarchy.

02 — Idle state (nothing selected)

Window open, agents alive, no selection. Agent Detail shows a placeholder; navmesh + stats + events still update live.

03 — Filtered list, multiple matches

Filter applied to the Agent List. No selection (or last selection no longer matches). Shows tag-based filtering.

04 — Navmesh health check failure

Navmesh Status panel shows red. Health Check button has been clicked, ran a synthetic FindPath, and failed. Hint row tells the user where to look.

How to read this mockup (for gate authors)

Each gate is responsible for adding the panels and fields it claims:

  • Gate 0 — Window opens, toolbar present, all panels visible but mostly empty. Console var ck.CrowdDebugger 1 works.
  • Gate 1 — Navmesh Status panel populated. Health Check button functional. Path visualization in PMG (not in the window itself).
  • Gate 2 — Agent List populated. Agent Detail "Identity / Position / Velocity / Goal / Path" sections.
  • Gate 3 — Agent Detail "Neighbors" section. Stats panel "Avg neighbors" field.
  • Gate 4 — Agent Detail "Sleep / Replan" rows. Event Log "Sleep / Pierce / Path Replan" categories. Stats "Asleep / Replanning" counts.
  • Gate 5 — Player Proxy entity in the Agent List with a distinct badge. Event Log "Proxy" category for soft-push activations.
  • Gate 6 — Stats panel frame-timing fields and sparkline. Filter / sort interactions in the Agent List polished.
  • Gate 7 — No new debugger features. Verify everything works at 100+ agents.

Color semantics (used everywhere): orange = selected/primary action; green = healthy; yellow = warning; red = error; cyan = info / cross-reference; grey = asleep / dim.
