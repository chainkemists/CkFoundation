# Authored command menus

Status: shared menu sessions, native menu-button, typed table/tree context targets and Resource Inspector consumers pass the 89-authoring/6-app checkpoint. Texture Health's installed copy command passes its native target regression. Scene Audit migration is implemented but currently rejected by the missing ordinary-button enabled binding. See ../PROGRESS.md for exact gate evidence; broader menu acceptance below remains open.

## First consumers

Texture Health OnContextMenuOpening currently constructs FMenuBuilder and a single Copy texture details entry in SCkTextureDebugger_TextureHealthTable.cpp. Scene Audit constructs two copy entries. FCkUiView currently accepts FDataBindings.TableContextMenus returning arbitrary native widgets, referenced by context-menu-action. Replace these presentation callbacks with authored menus; native copy/selection behavior stays in the consumer. Resource Inspector adds an Actions menu using the same contract before debugger migration.

## Declaration and runtime boundary

Add document-level menu declarations with stable ids, authored menu-item, separator, and submenu structure. A menu-item declares a stable key, localized literal label or label binding, optional tooltip and enabled/visible bindings, and a required native action. Add a menu-button leaf referencing a menu id, and a context-menu reference on tables/trees. Menus are declarations, not ordinary mounted layout children. Validate duplicate keys, missing references/bindings, incompatible attributes, submenu cycles and malformed descendants before factories or publication. Unknown styles remain explicit errors. Keep existing context-menu-action only as a transitional compatibility route and reject simultaneous old/new declarations.

Use one shared native menu presenter for buttons and context menus. Native Slate supplies popup hosting, item input and menu navigation. Authored documents own entry order, labels, separators and nested structure; consumer code must not construct FMenuBuilder or supply a widget subtree. Reuse typed actions/bool/text/image bindings and the view lifetime/event gate. Do not introduce a menu-specific string expression language or JavaScript.

A context menu captures the stable collection key at opening, not a mutable row index or a localized label. Add a typed context action invocation carrying that key, and resolve the current live row before dispatch. Removed keys disable/reject the operation. Consumer callbacks independently validate feature-specific availability. Plain menu-button commands have no row key. Never silently retarget an open row menu to a newly selected row.

## Ownership and publication

Opening snapshots a validated menu declaration plus a weak owner; live enabled/visible state remains model driven. Invocation rechecks owner/event gate, entry availability and target identity immediately before dispatch. Copy the callback before invocation and perform no stale accesses after callback-driven reload/removal. A compatible reload may dismiss this owned menu as an explicit first-version policy; do not promise popup preservation until tested. Invalid reload leaves the existing menu and view untouched. Removed owner or hidden ancestor closes only owned menus and releases owned focus/capture, respecting redirects and unrelated Slate users. Reuse the retained transient-interaction hook and popup focus ownership already established for select controls.

## Context-menu implementation boundary (source inspected)

The current button presenter owns entries, revision guards, submenu generation and weak popup roots. Extract these into a non-widget FCkUiMenuSession shared by menu-button and table/tree context hosts. Do not construct an invisible menu button to obtain popup content. A session builds native content and exposes explicit invalidation/owned-focus cleanup; the host retains the actual popup handle needed to dismiss its own menu. Menu-button keeps its SComboButton anchor; table/tree context hosting supplies native PushMenu ownership.

Add a typed context invocation carrying an immutable opening FString key, with a live target-availability predicate and no retained row pointer. Target validation must run on enable/dispatch and resolve the live collection before any consumer action. Current single-select semantics remain native. The local engine verifies STableRow.h:608 selects the row on right-button release, then invokes Private_OnItemRightClicked; SListView.h:1148 delegates to OnRightMouseButtonUp, and STableViewBase.cpp:1278 obtains/pushes content. Capture the actual clicked item key in this path, not a later selection getter that a consumer callback could normalize. Keyboard opening uses the current selected key explicitly. Blank-space context has no row target and must not reuse an old key accidentally.

SCkUiTable currently stores raw FOnContextMenuOpening; SCkUiTree has no context callback. Introduce the same typed target/session callback for both, with staged view preparation and existing parser action validation extended to the authored context-menu reference. Preserve legacy widget-producing callbacks only during migration. Add actual right-click/keyboard tests for unchanged selection, callback normalization, sorting/filtering/removal while open, and rejected/stale target dispatch before migrating Texture Health and Scene Audit.
### Native host details verified before extraction

STableViewBase.OnKeyDown only implements Ctrl+End before delegating to SCompoundWidget; it does not open a context menu. The new typed table/tree host must explicitly handle the context-menu key and Shift+F10 using current selection and a mounted anchor location. Pointer opening must preserve the actual item supplied to Private_OnItemRightClicked after native selection, even if the selection callback redirects the model. Existing Ck.UiAuthoring.Table.ContextMenu directly invokes list OnMouseButtonUp and proves callback configuration only; it does not prove hit-tested row targeting. Add routed row pointer tests for the new contract, retaining the existing legacy test during migration. Native PushMenu's returned IMenu must be retained by the host for owned dismissal; avoid DismissAllMenus in production cleanup.
